# 原型还原与视觉验收规格

Status: done
Date: 2026-10-30

## Problem Statement

学习者已经确认照片探索原型，但微信小程序加入了额外的大标题、说明和不同的词义卡样式；原生按钮默认宽度使图上标签变成长条。功能测试通过，无法证明页面外观与确认过的原型一致。后续实现缺少可追溯的视觉依据和明确的完成门槛。

## Solution

以已有交互预览的 daily1 状态为本轮直接视觉基准，还原照片优先、紧凑彩色图上标签、照片下方轻量提示和中性词义卡。用同尺寸基准截图、微信真实截图和差异记录同时验收。功能通过、视觉核对和已说明的平台差异分别记录，不能用其中一项替代另一项。

## User Stories

1. As a 学习者, I want 打开结果页首先看到原照片, so that 我能直接探索照片中的物体。
2. As a 学习者, I want 原图完整等比显示, so that 我能看到照片边缘的物体。
3. As a 学习者, I want 四个英文按文字长度形成紧凑标签, so that 标签不会成为遮挡照片的长条。
4. As a 学习者, I want 标签保持原型中的区分色, so that 我能持续辨认同一个学习对象。
5. As a 学习者, I want 默认标签白底彩字、选中标签同色底白字, so that 我能识别当前查看的对象。
6. As a 学习者, I want 点击不同标签只切换一张词义卡, so that 我能专注查看一个词。
7. As a 学习者, I want 词义卡使用原型的字号、间距、中性边框和浅灰背景, so that 原型中的体验能延续到小程序。
8. As a 学习者, I want 使用右上角 × 关闭词义, so that 我能回到默认引导并保留四个标签。
9. As a 学习者, I want 叉子标签通过细线指回历史指向点, so that 文字不会覆盖小物体。
10. As a 学习者, I want 关闭前后标签位置和颜色稳定, so that 探索不会被页面跳动打断。
11. As a 学习者, I want 页面保留简短的演示与位置未验证说明, so that 我不会把历史预览当成准确识别结果。
12. As a 产品负责人, I want 明确区分原型画面、原型外的调试面板和微信原生导航, so that 视觉还原范围可以核对。
13. As a 产品负责人, I want 固定同一画面尺寸对照默认、选中和关闭三态, so that 不会再仅凭功能正常宣布界面完成。
14. As a 产品负责人, I want 每项必要偏差都有原因, so that 新增文字和样式不会成为无依据的设计。
15. As a 后续开发者, I want 视觉尺寸和颜色有可追溯的统一来源, so that 后续页面不会再次漂移。
16. As a 后续开发者, I want 沿用结果页验收边界, so that 视觉修复不会迫使交互和数据层重新设计。

## Implementation Decisions

- 技术维持原生微信 JavaScript、WXML、WXSS，不引入框架、组件库、Tailwind 或暗色模式。
- 直接基准为已确认的本地交互预览 daily1，照片与原始四项 JSON 不变；花束截图只补充通用标签和卡片样式，不将花束业务或七项数据移入当前页面。
- 本轮无需读取 Figma。用户提供的指定节点作为补充定位；如本地证据不足，只读取该节点并缓存结果，不扫描整个文件。额度失败一次即停止，记录失败工具与完整错误。
- 页面内容区使用白背景，左右 20 CSS px；390 CSS px 视口下照片宽 350 px，照片圆角 16 px，完整保留原图 3:4 比例。小屏维持 20 px 边距并等比缩放照片。
- 由微信原生导航显示“识图结果”。不复制原型里的假状态栏、返回按钮、胶囊和 home indicator；这些区域不作像素一致比较。
- 移除照片上方新增的宣传式标题、眉题和范围说明；演示来源与适用范围保留到词卡下方的次要说明区域，不挤占照片首屏位置。
- 标签字体 12 px、600 字重、16 px 行高；水平内边距 7 px、垂直 5 px，1 px 同色边框，5 px 圆角。标签宽度必须随英文实际内容收缩；逐个验证不受微信默认按钮宽度影响。
- 四色严格沿用原型：plastic cup `#d53939`、glass `#2461d9`、napkin `#128247`、fork `#8734d0`。选中仅改变背景和文字色，不改变标签尺寸；不出现 √。
- 普通标签以历史 bbox 中心为显示依据，右边缘保证文字完整；只对 daily1 叉子配置预览中的向上偏移及同色细引线和中心点。属于展示坐标，不修改原始 bbox，不宣称位置有效性已经验证，不实现通用避让算法。
- 照片与词卡间提示为 11 px、18 px 行高、`#737373`，上下各 12 px。当前仅支持四标签，提示使用“点标签查看释义”，不显示尚未实现的圆点操作指引。
- 默认与选中词义卡共用外框：最小高度 148 px，16 px 内边距，8 px 圆角，1 px `#d8d8d8` 边框，`#f6f6f6` 背景。卡片选中时不改成彩色外框。
- 默认引导标题沿用“点标签，认识照片里的物品”：17 px、24 px 行高、粗体；说明 12 px、20 px 行高。引导说明适配当前能力，不承诺收起或点圆点。
- 选中卡英文为 17 px/24 px 并使用对应标签色；中文 14 px、600；原始解释 12 px/20 px。右上 × 为 25 px 字形、36×36 px 点击区域、透明背景，不显示宽大的“关闭”按钮。
- 不添加当前无法工作的“切换体验照片”“收起标签”按钮。它们在原型中存在，但属于后续任务的真实能力；作为有理由的阶段差异记录。
- 视觉值采用本轮约定的统一令牌。组件不能自行增加标题、描边、阴影或改变颜色；需要调整时先更新依据和偏差记录。
- 功能与视觉分别记录；视觉状态不因页面级行为测试通过而自动通过。

## Testing Decisions

- **已确认验收边界**：用户回复“修正页面”，继续使用现有结果页入口、真实 WXML 和可替换来源；追加同尺寸原型与微信截图对照。
- 好的行为测试只检查装载、点击、切换、关闭和可见内容，不测试内部布局函数或私有状态。
- 沿用现有页面模拟测试，保护四项数据、同名对象独立选择、原始数据不变和标签色恢复。
- 微信内验收继续使用现有自动化入口；增加对真实标签宽度、字号、卡片边框/背景、关闭区域和内容区边距的测量。静态模板匹配不替代微信布局测量。
- 主验收视口固定为 390 CSS px；保存原型 daily1 默认及 plastic cup 选中基准图，保存微信默认、相同词选中、关闭恢复截图。记录 CSS 视口与截图像素密度，比较内容区域，排除系统导航与安全区。
- 辅助检查 375 CSS px：无水平裁切，词卡能完整阅读和关闭。原型桌面工具栏不作为小程序桌面适配目标。
- 同尺寸下边距、照片宽度、卡片外框位置偏差不超过 2 CSS px；字号、边框、圆角、颜色按令牌核对。字体栅格和平台字体差异单独列明，不以全图像素差分百分比掩盖结构错误。
- 标签可见框不应统一等宽；默认和选中切换尺寸偏差不超过 1 CSS px；关闭后四个标签的样式及位置与默认一致。
- 人工查看截图：照片优先、紧凑标签、叉子细引线、原型式词卡、×；不存在新增大标题、长条默认按钮、彩色卡片边框或勾选图标。
- 关闭恢复截图与默认截图可以比较，但记录时间和系统 UI 变化，不要求系统区域完全一致。
- 若微信不可连接，如实保留未验收项；不将浏览器或模拟渲染作为微信验收通过。视觉基准来自浏览器并明确标记，不伪装成微信画面。

## Out of Scope

- 修改 Figma 文件、扫描整个 Figma 文件、重做原型、替换原照片或原始识别名称与解释。
- 实现花束样本、额外圆点、展开/收起、相册选图、识别 API、通用引线或碰撞避让、严格 anchor 验证、错误重试。
- 将整个浏览器临时原型复制为正式小程序，复制调试面板、假系统栏或无法工作的操作按钮。
- 登录、分享、发布、真机适配完成声明及新建组件库。
