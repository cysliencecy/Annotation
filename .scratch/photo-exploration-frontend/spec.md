# 拍照学英语：小程序前端与照片探索交互规格

Status: ready-for-agent
Date: 2026-10-29
Feature: photo-exploration-frontend
Approved: 用户于 2026-10-29 确认页面级验收边界、本地 Markdown 任务跟踪、AGENTS.md 与默认状态词方案。

## Problem Statement

自用学习者希望从一张日常生活照片认识物体的英文名称。单纯列出词汇很难知道每个词指向哪里；一次铺开所有标签又容易遮挡照片。用户需要在原图上先看见少量英文，再通过圆点逐个探索其他已经识别的物体，并按需查看中文含义。

现有浏览器临时预览已经让项目作者确认这套探索交互，但它只切换预置照片，未接入微信相册、真实识别或小程序运行环境。已有 Python 工具用于静态回绘，不能承担小程序的交互功能。

本规格解决下一阶段的小程序前端开发：用明确标识的演示数据走通页面、坐标映射与交互，分清显示问题和模型问题，为后续真实识别接入建立边界。

## Solution

实现一个可在微信开发者工具及真机中体验的前端闭环：进入页面、选择或预览照片、查看预置样本的图上标签与圆点、展开英文、查看词义、关闭或收起，并体验加载、失败、重试和换图状态。

结果页初始自动展开最多 5 个英文标签，其余有有效位置的已识别对象显示彩色圆点。点击圆点只展开英文；点击英文再显示词义卡片。连续展开不收起其他标签，允许显示第 6 个、第 7 个英文。卡片关闭保留标签；“收起标签”把当前标签变回圆点。

每个对象使用稳定的区分色，圆点、英文文字和引线同色。默认白底彩色字，选中后同色底白字，不显示 √。标签优先位于目标中心，小物体或碰撞时移到旁边，以引线连接有效指向点。移除“更多词汇”。

本阶段以预置样本验证结果页，接入相册验证真实选图能力；二者明确区分。新选照片没有匹配演示结果时，只展示照片及“识别服务尚未接入”的可理解状态，不给它套用其他照片的标签。真实 GLM-5.3-Flash 调用不属于本规格的完成条件。

## User Stories

1. 作为自用学习者，我希望知道适用照片是清晰、彼此分开的日常物体照，以便选择合适的图片。
2. 作为自用学习者，我希望从微信相册选择一张照片，以便在小程序里预览自己的照片。
3. 作为自用学习者，我希望取消相册选择后保留原来的页面，以便不会因为一次取消而丢失当前结果。
4. 作为自用学习者，我希望完整看到照片，以便标签指向的位置与我看到的物体一致。
5. 作为自用学习者，我希望明确知道自己正在体验演示结果，以便不把固定 JSON 当成对新照片的实时识别。
6. 作为自用学习者，我希望打开演示照片就能看到最多 5 个英文标签，以便立即理解页面的用途。
7. 作为自用学习者，我希望只有 4 个有效对象时只显示 4 个标签，以便结果不会为了凑数而添加猜测。
8. 作为自用学习者，我希望额外的已识别物体用圆点提示，以便知道照片中还有可以探索的词。
9. 作为自用学习者，我希望点击圆点只展开英文，以便先看英文、尝试回忆，而不是立刻看到中文答案。
10. 作为自用学习者，我希望连续点开额外圆点后已有标签继续保留，以便比较和浏览多个物体的英文。
11. 作为自用学习者，我希望点击英文标签查看英文词、中文名称和一句简短解释，以便理解这个词。
12. 作为自用学习者，我希望当前查看的标签变成同色底白字，以便知道词义卡片对应哪个物体。
13. 作为自用学习者，我希望点击其他英文标签切换当前词义，以便继续学习而不叠加多张卡片。
14. 作为自用学习者，我希望关闭词义卡片后标签仍然显示，以便继续观察照片。
15. 作为自用学习者，我希望在卡片中收起当前标签，以便把它变回圆点、减少照片上的文字。
16. 作为自用学习者，我希望收起一个标签不会改变其他标签，以便我已展开的内容不会意外消失。
17. 作为自用学习者，我希望再次点开收起的圆点时仍然只看到英文，以便操作规则前后一致。
18. 作为自用学习者，我希望每个对象的圆点、文字和引线使用同色，以便在复杂照片中对应到同一个物体。
19. 作为自用学习者，我希望叉子等小物体的标签放在旁边并有引线，以便文字不会遮住物体本身。
20. 作为自用学习者，我希望能放下的标签避开其他文字与圆点，以便读得清楚，也能点击剩余入口。
21. 作为自用学习者，我希望点照片中没有标记的位置时不会触发识别，以便不会误以为每个物体都能临时识别。
22. 作为自用学习者，我希望识别加载状态清楚且不会把上一张照片的结果画到新照片上，以便理解当前正在处理什么。
23. 作为自用学习者，我希望失败、空结果或定位异常有明确提示和重试、换图入口，以便知道下一步能做什么。
24. 作为自用学习者，我希望重新得到一份结果时回到初始展开状态，以便不同照片之间不会混用标签或选中状态。
25. 作为项目作者，我希望用 4 项和 7 项真实历史样本体验完整交互，以便检查少于 5 项与超过 5 项两种情况。
26. 作为项目作者，我希望演示数据、历史 bbox 中心预览和新模型有效 anchor 有明确区别，以便显示正确不被误认为模型能力已经通过验证。
27. 作为后续开发者，我希望用同一个结果页替换演示数据来源，以便接入真实识别时保留已确认的交互行为。

## Implementation Decisions

### 1. 交付阶段与模块边界

- 交付微信小程序前端，包含照片选择与预览、结果页、词义卡片、加载与异常状态。当前仓库没有小程序工程；开发任务需要包含工程初始化和微信开发者工具运行说明。
- 技术框架与语言尚未选定，不在规格中假定已有框架、组件库或自动化工具。选择时以微信开发者工具运行和本规格的页面操作验收为依据，避免新增与需求无关的跨端层。
- 页面使用一个结果会话边界，接收当前照片、对应识别结果和用户操作，产出图上标签、圆点、引线及当前卡片状态。状态与布局可以在边界内部拆分，但不要求为每个内部函数建立独立测试入口。
- 照片选择依赖微信平台能力；识别结果来源通过一个可替换的数据来源边界提供。本阶段提供受控的演示结果、延迟、失败及空结果；后续真实识别复用这一入口，不在标签点击事件中直接调用模型。
- 复用临时预览中已经确认的行为，不把临时代码直接当作生产实现，也不复制 Figma 中枚举大量页面的做法作为小程序状态实现。

### 2. 演示数据与照片对应

- 演示照片和原始 JSON 必须一一对应。相册选择任意新照片后，不自动使用 daily1 或花束的 JSON 给新照片标注。
- 演示入口与真实选图入口可区分；预置样本结果明确标识为演示。加载与失败可由开发验收控制的数据来源触发，不把这些控制选项混入正常学习页面。
- daily1 的 4 项数据用于日常标签、叉子引线及带简短解释的词义卡片；flower1 的 7 项数据仅用于初始 5 标签、2 圆点及连续展开，不扩大日常 MVP 的识别范围。
- flower1 的原始记录没有一句中文解释，不补写后冒充模型结果。该历史演示卡片可以只显示已有英文和中文名称，并在演示说明中披露字段缺失；完整词卡内容以带解释的日常数据验收。
- 历史样本缺少 anchor 时，仅允许在明确的历史演示模式下，从 bbox 中心生成视图点，并注明定位尚未验证。这个临时视图不写回原始 JSON。

### 3. 输入、校验与结果身份

- 一份结果包含 objects 数组。日常新结果的每项包含 name_en、name_zh、description、bbox 和 anchor；名字与解释为字符串，bbox 为四个数值，anchor 为两个数值，坐标以完整图片为基准归一化到 0–1000。
- bbox 满足左右、上下边界递增且在 0–1000 内；anchor 在同样范围内并落在自己的 bbox 内。几何校验不代表名称或指向在语义上正确。
- 为每份结果和其中每个对象建立仅用于前端会话的稳定身份，以关联展开状态、选中状态、颜色和布局。身份不能依赖当前文字位置或排序后的显示序号；同名记录也不能因名称相同而意外合并。
- 原始结果保留，不通过重命名、调整坐标或补造置信度修正模型结果。无有效位置的对象不画标签或圆点；没有可展示对象时进入明确的空结果或定位异常状态。
- 原始名称错误与界面显示错误分开记录。对后续真实模型返回的缺字段、格式错误、无效位置，不静默套用历史演示的兼容规则。

### 4. 结果页状态与事件

每份结果维护“已展开对象集合”和“当前选中对象”。其余合格且可定位的对象显示探索圆点。当前最多选中一个对象、显示一张词义卡片。

| 事件 | 展开集合 | 选中对象与卡片 | 其他约束 |
| --- | --- | --- | --- |
| 装载一份新结果 | 初始候选中的最多 5 项 | 无选中，无卡片 | 建立该结果的对象身份与颜色。 |
| 点击圆点 | 加入该对象 | 不新开卡片；若已在看其他对象，保留当前卡片 | 不移除其他已展开对象，不请求模型。 |
| 点击已展开英文 | 保持 | 选中该对象，显示对应卡片 | 原选中标签恢复默认样式。 |
| 关闭卡片 | 保持 | 清除选中，关闭卡片 | 所有已展开标签保留。 |
| 在卡片中收起标签 | 只移除当前选中对象 | 清除选中，关闭卡片 | 对应对象恢复圆点；其他对象保持。 |
| 点击无标记位置 | 保持 | 保持 | 不识别、不新增对象。 |
| 布局尺寸改变或重新排版 | 保持 | 保持 | 不按“先展示 5 个”重新截断集合。 |
| 换图或重试后成功装载新结果 | 重新初始化 | 清除旧选中 | 不携带旧结果的展开状态。 |
| 取消相册选择 | 保持原会话 | 保持 | 不清空已有照片与结果。 |

状态不持久化到登录账户或历史记录。初始 5 项只是初始展示规则，不能作为当前展开集合大小、数据截断或模型识别总数的硬限制。

### 5. 初始选择与颜色

- 产品目标是自动优先选择识别依据充分、主体清楚且标签容易放下的对象。现有 JSON 没有置信度，不能补造分数，也不能声称已实现可靠性排序。
- 本阶段演示样本按原始结果顺序选择前 5 项，作为确定、可复现的初始选择；这只是演示策略。真实结果的优先级排序需在模型接入前验证。
- 使用已确认的红、蓝、绿、紫等区分色，至少覆盖现有 7 项样本。一个对象的颜色在展开、选中、关闭、收起、再次展开及重新排版后保持稳定，不因点击顺序改变。
- 默认标签白底彩色字；选中标签同色底白字，不能添加勾选标记。圆点与引线使用同对象颜色。可点击形状、引线和文字共同建立对应关系，不仅依靠颜色表达可操作性。

### 6. 图片、坐标与布局

- 图片完整等比显示。坐标映射使用实际图片显示区域的宽、高和偏移；容器留白不能计入图片坐标，不通过裁切或拉伸改善排版。
- 标签首选位置以代表对象中心为中心。真实 anchor 负责指向，不能用 bbox 中心替换新结果的 anchor；文字位置与指向点分开管理。
- 小物体以显示后的对象范围与标签尺寸比较；文字可能遮挡物体时移到旁边。发生碰撞时同样允许移开，以同色引线连回原指向点，不能移动模型坐标。
- 已展开标签、探索圆点以及图片边界都参与布局约束。排版变化不改变对象身份、颜色、已展开集合或当前选中项。
- 布局实现需在现有样本与支持的手机尺寸上检查可读性和可点击性。临时预览中“选择冲突较少的候选位置”只是探索实现，不是极端密集照片的已确认兜底方案。

### 7. 加载、失败与换图

- 页面状态至少区分：未选图、照片预览、等待结果、结果可用、空结果、格式或定位异常、数据来源失败，以及当前阶段的识别服务未接入。
- 请求中的照片与结果使用同一会话标识关联。等待期间换图或再次发起请求，旧请求的迟到结果不能覆盖当前照片或当前结果。
- 数据来源失败、空结果或无可展示位置时，显示可理解的原因和重试、换图入口，不制造占位对象、错误成功数量或随机标签。
- 本阶段重试通过演示数据来源验证重新请求和状态恢复；不宣称真正调用了 GLM。任意新选照片的“服务未接入”不能伪装成“模型未识别到物体”。

### 8. 尚未决策的边界

- 识别结果总数上限：保持待确认。前端不能硬编码“总数最多 5”，但本规格不据此承诺识别无限多对象；更大规模、配色和性能范围需在上限确定后落实。
- 极端拥挤：标签已避让仍放不下、圆点密集到无法区分的处理保持待确认。不得擅自恢复“更多词汇”、自动收起已有标签、强行叠字或移动目标点。
- 这些问题不阻塞当前可清楚摆放样本的前端开发；遇到此类案例应保留证据并回到决策，不把它们标成已通过的通用能力。真实识别上线前需要关闭这些决策缺口。

## Testing Decisions

### 已确认的主要验收边界

**以结果页的用户操作为主要测试边界**：注入当前照片及对应的受控识别结果，执行点击圆点、英文标签、关闭、收起、重试和换图，观察用户可见的照片、标签、圆点、卡片和提示。只有数据来源与微信相册能力需要替代或平台适配，不为内部渲染函数、候选位置列表或私有状态字段分别建立测试入口。

用户已于 2026-10-29 确认这项边界；本规格按本地任务约定发布并标记为 ready-for-agent。识别总数上限、极端拥挤等后续决策仍按上述阶段范围处理，不因此视为已解决。

### 好的测试与已有基础

- 测外部行为和完整操作顺序，不断言私有函数调用次数、内部数组排列、Figma 节点 ID 或某一组固定排版像素。实现换成组件、状态机或其他内部结构时，行为测试应仍然成立。
- 已有浏览器预览及其操作检查记录可作为行为范例，尚无可复用的小程序工程、自动化测试框架或测试套件。Python 静态回绘不等同于小程序页面测试。
- 优先使用小程序运行环境可驱动的页面级行为测试；具体工具在工程初始化时选择，避免为同一交互并行引入多套测试框架。
- 坐标和布局检查以图片范围、有效指向点、文字边界与可点击目标为依据。截图与真机检查补充遮挡、碰撞、颜色对比和触控体验，不能用截图证明模型名称或定位准确。
- 在本阶段的验收中，可替换识别结果来源以控制延迟、失败、空结果和返回顺序；相册选择、取消与图片显示需在微信平台做人工或平台支持的自动化检查。
- 测试数据可以有独立的明确标识的模拟对象，用于有效 anchor、无效数据和异步情形；不得写回历史原始 JSON，也不得作为模型实测结果保存。

### 必须覆盖的验收场景

| 场景 | 可观察的通过条件 |
| --- | --- |
| daily1 四项历史演示 | 4 个英文标签，无额外圆点；说明使用的是历史中心点预览。 |
| flower1 七项历史演示 | 初始 5 个英文、2 个圆点；没有“更多词汇”；不把样本当成日常花名识别上线。 |
| 连续展开额外对象 | 变为 6 标签 1 圆点，再变为 7 标签 0 圆点；其他已展开对象保持。 |
| 圆点与词卡分两步 | 点圆点不新开词卡；再点该英文才显示对应词义。 |
| 切换当前词义 | 只有一个选中标签和一张卡片；显示内容与新选中对象对应。 |
| 关闭后继续探索 | 卡片关闭、标签恢复彩色文字，展开数量和其余圆点保持。 |
| 收起与再次展开 | 只有目标标签变回圆点；再次展开不直接打开词卡、不影响其他对象。 |
| 查看一个词时展开另一个圆点 | 保留原卡片，新增英文不抢占选中；之后点击新英文才切换卡片。 |
| 全部收起再展开 | 允许没有已展开英文、只剩圆点；可逐个展开，且不重新限制到 5 个。 |
| 小物体与边缘目标 | 叉子文字不盖住物体；引线回到有效点；边缘标签不被图片裁掉。 |
| 改变显示尺寸 | 图片不变形、不裁切；指向仍落在对应图片坐标；展开与选中状态保留。 |
| 无标记区域点击 | 不出现新标签、不调用识别结果来源。 |
| 空结果与无有效坐标 | 有明确异常或空状态；没有伪造标签或圆点；存在重试、换图入口。 |
| 新结果缺失 anchor | 按新结果契约处理异常，不静默使用历史 bbox 中心兼容。 |
| 调用失败后重试 | 展示失败及可恢复入口，重试使用当前照片，成功后建立新结果状态。 |
| 请求 A 未完成时换到 B | A 的迟到成功或失败都不覆盖 B 的照片、结果或提示。 |
| 相册取消和任意新照片 | 取消不破坏当前状态；新照片不套用演示 JSON，服务未接入如实提示。 |
| 原始数据完整性 | 展开、移动文字、收起、重试不会改写模型原始名称、解释或坐标。 |

阶段完成需要在小程序里运行上述适用场景，不能仅凭浏览器预览通过或静态截图判定小程序已完成。
