# 照片标签展示规则

状态：2026-10-28 更新。几何含义与定位要求适用于四类离线验证；下文“当前 MVP 交互”以[自用 MVP 定义](../MVP定义.md)为准，替代 2026-10-21 的“更多词汇”方案。食物、风景和鲜花的离线对象上限仍按各场景提示词执行；日常 MVP 的识别总数上限待确认，初始展开最多 5 个英文标签。

四类提示词已加入 `anchor` 要求；food2 至 food5 已有定向输出，其余仍待实测。回绘脚本支持静态画点和几何校验，浏览器临时预览支持探索交互；小程序布局与真实识别服务尚未接通。

## 核心含义

- `bbox`：模型认为目标可见部分所在的范围。对分散的同类物体，仅框一个清楚的代表，不把所有同类合成大框。风景中连续、清楚的天空或水面可以是较大区域。
- `anchor`：标签应指向的画面位置，格式 `[x, y]`，与 `bbox` 同用原图左上角为原点的 0–1000 坐标。具体物体应落在所选代表的可见部分；风景区域应落在能明确认出该区域的位置。
- 文字位置：显示端安排的标签底板位置。优先以物体中心为文字中心；需要避免遮挡或碰撞时移到旁边，用引线连接有效 `anchor`。物体中心与可靠指向点可能不同，不能用 bbox 中心替代新结果的 `anchor`。移动文字不能修改模型的 `bbox` 或 `anchor`。
- 探索圆点：已识别但尚未展开英文的对象入口，放在该对象的有效指向点；点击只展开已有英文标签，不调用模型，也不直接打开词义卡片。
- 原始识别结果：无论标签展开还是收起都保留。初始展开数量、当前展开数量和模型识别结果总数是三个不同的数量。

新模型结果的每个对象增加 `anchor`，其余字段按场景提示词保持。例如花朵：

```json
{"objects":[{"name_zh":"康乃馨","name_en":"Carnation","bbox":[620,460,730,510],"anchor":[675,485]}]}
```

历史 JSON 没有 `anchor`，离线和临时交互预览暂取 `bbox` 中心；这不表示中心点已通过定位检查。新结果若 `anchor` 超出 0–1000、落在自身 `bbox` 外或坐标无效，不为该结果伪造标签、引线或圆点，按 MVP 的定位异常处理；原始输出仍保留。坐标在框内也仅通过几何检查，仍需核对是否落在真正命名的目标上。

## 当前 MVP 交互

1. 系统先识别一批合格物体，自动展开最多 5 个英文标签。优先选择识别依据充分、主体清楚且标签容易放下的对象；现有 JSON 没有置信度分数，不伪造分数，具体排序方式待实现验证。其余有有效位置的结果显示圆点。
2. 点击圆点只展开对应英文。已有标签保留，允许继续展开第 6 个、第 7 个；5 个不是当前展开数量或识别总数的硬上限。
3. 点击英文标签显示其词义卡片，并切换当前选中对象。每个物体的圆点、英文文字和引线使用同一种区分色；默认白底彩色字，选中后同色底白字，不显示 √。颜色不表示类别或置信度。
4. 关闭卡片后保留标签并恢复默认样式。“收起标签”关闭对应卡片、让该标签变回圆点，其余已展开标签保持。再次点击圆点仍只展开英文，不直接打开词卡。
5. 不提供“更多词汇”或图片下方的完整词汇列表。点击无标签、无圆点的位置不触发新识别；圆点只代表已有结果。
6. 完整显示原图，按原图宽高映射 0–1000 坐标，不通过裁切改善布局。收起标签只改变显示状态，不是删除结果或人工修改名称、点位。

## 摆放规则

| 情况 | 处理 |
| --- | --- |
| 天空、水面等大片连续区域 | 标签仍在照片上，放在区域内清楚、可读的位置，不强制使用框中心；文字仍在区域内时不画指向线。 |
| 边界清楚、大小足以容纳标签的单体或花朵 | 优先以物体中心为文字中心，检查底板是否挡住辨认特征。需要移开时，短线连回有效 `anchor`。 |
| 葱花等小物体 | 只在能可靠识别和定位时保留；文字放到旁边，用小点和短线指回 `anchor`，避免底板盖住目标。是否属于“小物体”按显示后的目标与标签尺寸比较，不预设固定原图像素门槛。 |
| 分散的同类物体 | 每类仅选一个清楚代表，把 `bbox` 和 `anchor` 指向这一块；找不到可指向的代表时跳过该类，不用大框概括全部。 |
| 两个标签碰撞 | 保留各自 `anchor`，移动文字、避开主要主体，再用各自颜色的短线连接。展开新标签不自动收起已有标签；避让后仍放不下的极端情况待继续确定，不恢复“更多词汇”兜底，也不强行叠字。 |
| 尚未展开英文的已识别物体 | 在有效指向点显示圆点，保留可点击区域；不要让已展开文字挡住圆点。圆点自身发生密集碰撞的处理待继续验证。 |

低依据、无法可靠命名的候选仍按识别规则跳过，不为了提供更多圆点而增加猜测结果。2026-10-21 版本曾使用“更多词汇”容纳放不下或无有效位置的结果；该交互已被当前 MVP 的图上圆点方案替代，不能继续作为小程序实现依据。

## 实施顺序与验收观察

1. 四类提示词已增加逐对象 `anchor`。food2、food3 的定向回绘发现小配料点位问题；food4 新图发现米饭与肉片互相指错；food5 的点位较好，但主食材框过大。后续复测不能只验证小目标。名称、去重和 `bbox` 原有规则继续适用；日常识别总数上限需另行确定，其他场景仍沿用各自离线提示词上限。保存原始模型输出，不人工修正后冒充模型结果。
2. 可视化脚本已能用 `--show-anchor` 回绘 `bbox` 和真实 `anchor`，并保留旧 JSON 的中心预览。下一步才是移动后的文字和指向线；先对现有失败样本检查点是否在目标上，再判断文字摆放。
3. 在手机尺寸的原型上检查文字阅读、目标遮挡、标签与圆点碰撞，以及“圆点 → 英文 → 词义卡片 → 关闭保留 / 收起为圆点”的状态变化。记录结果总数、初始展开数、当前展开数和圆点数，确认连续展开不会收起其他标签；不设未经测试的准确率或尺寸门槛。
4. [临时交互预览](../../prototypes/exploration-throwaway/index.html)已用于确认交互；daily1 有 4 项，flower1 有 7 项。花束只作为超过 5 项的交互样本，前 5 项按原 JSON 顺序展示，不证明系统排序、名称、定位或日常识别超过 5 项的能力。生产端还需验证真实输出与布局。

定向检查样本：[scenery1 的宽区域](../../outputs/scenery/scenery1-center.png)、[food2 的葱花](../../outputs/food/food2-anchor-r1.png)、[food3 的分散洋葱](../../outputs/food/food3-anchor-r1.png)、[flower2 的密集花束](../../outputs/flowers/flower2-center.png)。模型名称错误、`anchor` 指错物体、文字遮挡和移动后指向线错误须分别记录；布局无法补救前两种模型错误。当前 `visualize.py` 支持框上缘、框中心和真实锚点的静态诊断，不支持引线及碰撞避让。
