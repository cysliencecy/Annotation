# 识图方案讨论记录

## 已确认

- 食物场景按食材类别标注，例如肉片、洋葱、香菜各标一次，不逐片或逐瓣重复标注。用户于 2026-10-20 选择方案 B。
- 同类只出现一个标签，每张最多 5 个，不为凑满数量添加对象。
- 可辨认食材超过 5 类时，先排除看不清或无法明确定位的对象，再优先选择画面中显眼、代表对象较大且完整的食材；小配料和点缀放后面。用户明确接受此选择顺序。
- 同类食材只框最清楚的一个单体或边界清楚的一小簇，作为代表对象；不跨越其他食材将分散的同类全部圈入一个大框。用户选择框选方案 B。
- 小物体或被遮挡的食材，仅在有足够外观依据判断类别、且边界框能明确指向对象时标注；否则跳过，允许不足 5 个。暂不设置固定像素门槛，后续用回绘结果验证是否需要尺寸限制。用户选择清楚才标的方案 B。
- 食物场景只标注食物，排除碗、盘、杯、筷子、包装、桌面等非食物对象，用户明确接受。此限制不用于日常随手拍场景，日常场景仍可识别杯子等物体。

- 命名采用图片有依据支持的最具体名称；细分类不确定就退到大类，大类也无法判断就跳过。用户明确接受。例如无法判断肉种但能看出片状时，用“肉片 / meat slices”；只能判断是肉时，用“肉 / meat”。“烤制”“腌制”等修饰也需要依据，不能用“烤肉”作为通用兜底名称。
- 解释与名称遵守同样的证据边界，不能名称退到大类后，又在解释中断言具体肉种或处理方式。
- 简短解释采用一句中文词义解释，可以提供与最终名称对应的可靠通用知识，不将通用知识表述成对图中对象的具体判断。例如“胡萝卜是一种常见的根类蔬菜”；若名称为“肉片”，解释为“切成片状的肉”。不推测图中食物的口感、做法或新鲜程度。用户选择方案 B。

- 遮挡情况下仅框选代表对象的可见部分，不推测被遮挡的完整边界。矩形框允许包含少量背景或遮挡物，不要求像素级抠图；可见部分不足以辨认时跳过。用户选择方案 A。

- 同一组食物不同时标整体和局部。例如能分别辨认草莓、蓝莓时，只标各自代表对象，不再返回覆盖它们的“浆果”或“水果拼盘”；只能确认是浆果时才退到“浆果”大类。同一食物不以多个层级重复占用标签。用户明确接受。

- 模型负责返回对象的真实边界框，不为文字避让而改变框；显示端负责移动英文标签，必要时用引线连接对象。验证时分别记录定位是否正确与文字是否遮挡。用户明确接受该分工。

这些是产品规则，不是模型能力已通过验证的结论。已整理为[食物识图提示词 v2](../prompts/食物.md)，已完成初步复测；结果见[食物复测记录](../reviews/食物.md)。标签避让脚本未修改。
