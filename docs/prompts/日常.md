## 可复制的提示词

```text
请分析上传的日常生活照片，为拍照学英语功能选择并定位最多 5 个不同类别的对象。只返回最终 JSON，不输出 Markdown、分析过程或额外说明。

先在内部寻找候选对象，再逐个执行“存在、单体、命名、边界框、指向点、去重”检查。任何一项不能通过，就删除该候选。宁可少返回，也不要猜测或凑满 5 个。

一、候选对象
1. 可以选择清楚可见的人物、动物、植物和日常物品，包括杯子、盘子等；不要求每种类型都出现。
2. 对象必须能直接从图中外观确认，并且能明确定位。不得根据场景推测可能存在的对象。例如看到宠物用品不能推测有宠物，看到花盆不能把不清楚的区域猜成猫。
3. 先排除严重模糊、过小、遮挡过多或无法明确定位的对象。在剩余对象中优先选择较近的对象；距离无法可靠判断时，优先选择外观和边界更清楚的对象，不强行判断远近。
4. 不返回天空、地面、墙面、桌面、成片草木、整排或整叠物品等无法对应一个清楚单体边界的背景或集合区域。

二、单体与去重
1. 一个对象记录必须对应一个可分离的代表单体。多个同类物体只选择其中边界最清楚、位置较近的一个。
2. 禁止用一个框圈住多本书、多个杯子、整叠托盘、成片植物或其他同类集合。若无法从集合中分离出一个清楚单体，就跳过该类别。
3. 优先标注可辨认的整体，不同时返回整体及其部件。例如返回 bicycle 后，不再返回它的 wheel 或 handlebar。若照片只有局部特写、无法辨认整体，才标注可确认的部件。
4. 相连但可独立学习的物品可以分别标注，例如 dog 与 leash、laptop 与外接 mouse、vase 与 flower。
5. 按语义类别去重，不仅比较英文字符串。cup、glass、plastic cup 等杯状饮用容器通常只保留一个清楚且较近的代表；只有图片能明确支持它们是不同类别，并且分别学习确有意义时，才可同时返回。

三、名称与解释
1. 使用图片有依据支持的最具体名称；细分类不确定时退到可确认的大类。基本类别也不能确认时跳过，不使用 thing、object 等空泛词凑数。
2. 不猜人物身份、动物品种、植物种类、品牌、材质、状态或用途。只有图片能清楚支持时才能添加这些修饰。
3. name_zh 与 name_en 必须指同一个对象，具体程度完全一致。若中文包含“塑料、玻璃、木制”等材质，英文也必须包含对应材质，且图片必须能够可靠证明；否则两种语言都退到基础类别，例如“杯子 / cup”。
4. 英文使用常见、正确且适合学习的名称。不要为了制造不同类别而改用近义词。
5. description 使用一句简短中文解释最终名称的通用含义，不描述图中对象未经确认的品牌、材质、品种、性情或状态。解释的具体程度不得超过名称。

四、边界框
1. bbox 只覆盖所选代表单体的可见部分，贴近其可见部分的上下左右边缘；不推测被遮挡或画面外的完整范围。
2. 矩形允许包含少量背景或遮挡物，但命名对象必须是框内主要内容。若框内主要内容是其他物体、背景或多个同类对象，删除该候选，不返回这个框。
3. 不为了包含全部同类、完整场景或给文字留位置而扩大、移动边界框。显示端负责英文标签避让。
4. bbox 固定为 [xmin, ymin, xmax, ymax]。以完整输入图片左上角为原点，x 向右、y 向下；横坐标按图片宽度、纵坐标按图片高度分别归一化到 0–1000。
5. 坐标使用数值，必须满足 0 <= xmin < xmax <= 1000，0 <= ymin < ymax <= 1000。不要返回 0–1 或原始像素坐标。
6. 每项增加 anchor: [x, y]，使用与 bbox 相同的 0–1000 坐标。anchor 应位于自身 bbox 内，实际落在所选单体的可见部分，不能指向背景、其他物体或同类集合的空隙。小物体也要指向清楚可见的部分；找不到可靠落点就删除该候选。
7. anchor 只表示目标点，文字位置由显示端处理，不为了文字避让改变真实 bbox 或 anchor。

五、输出前逐项删除检查
对每个候选依次确认：
1. 图中确实存在这个对象，而不是根据场景猜测。
2. 框对应一个清楚单体，不是背景、集合或同类物体的大范围。
3. 框内主要内容就是 name_zh 和 name_en 所指对象。
4. 中英文具体程度一致，所有修饰都有图片依据。
5. 与其他结果没有同类、近义词或整体部件重复。
6. anchor 在 bbox 内并确实落在命名对象的可见部分。

任意一项不能确认，就删除该对象。删除后无需补足数量。没有候选通过时返回 {"objects":[]}。

六、输出格式
顶层仅包含 objects 数组。每个对象仅包含以下字段，不增加其他字段：
- name_zh：中文名称字符串
- name_en：英文名称字符串
- description：一句简短中文释义字符串
- bbox：[xmin, ymin, xmax, ymax] 四个数值
- anchor：[x, y] 两个数值，位于 bbox 内并指向代表单体

结构示意，必须替换为当前图片中的真实结果，不要照抄占位内容：
{"objects":[{"name_zh":"中文名称","name_en":"English name","description":"一句中文释义。","bbox":[100,100,200,200],"anchor":[150,150]}]}

只输出最终 JSON。
```

## 回归测试方法

1. 用相同模型和可见参数，在新对话中上传 daily1 至 daily4，每张发送本页完整提示词，不附旧 JSON 或标注图。结果使用新的 `results/daily/daily1-anchor-r1.json` 等文件名，保留既有 v2 证据。
2. 分别检查对象是否真实存在、是否只框一个代表单体、中英文是否对应；再检查 anchor 是否在 bbox 内、是否落在命名目标的可见部分。daily2 的疑似猫必须独立核对，点落在某处不证明该处存在猫。
3. 用回绘脚本的 `--show-anchor` 画出模型给的点，人工核对是否指中目标；不能据 bbox 中心预览判断点位正确。文字碰撞与目标遮挡仍需后续手机原型检查。

这些旧照片只做定向回归；后续还需新日常照片验证。坐标范围合法不等于定位正确，anchor 在框内也不等于指对物体。
