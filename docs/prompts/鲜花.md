# 鲜花识图提示词

当前版本：在 v2 基础上增加逐对象 `anchor`，用于下一轮定位测试；尚未实测。既有结果见[鲜花复测记录](../reviews/鲜花.md)。

本版将每张照片的识别上限由 5 种提高到 10 种，按不同常见花名计数，同种花只返回一个代表位置。其余识别与定位规则沿用 v1。该上限由用户确认，已完成三张小样本初测，识别和定位仍有问题。

## 可复制的提示词

```text
请识别上传照片中的鲜花，返回最多 10 种能够可靠判断常见花名的花，以及每种花一个清楚的代表位置。只输出 JSON，不输出 Markdown、分析过程或额外说明。

识别规则：
1. 一张照片可以有多种花，请检查清楚可见的不同花类，不要只识别最显眼的一种。
2. 只识别花朵或花序。纯配叶、果枝、花盆、包装和其他装饰材料不返回。
3. 以常见花名为目标，不强求具体园艺品种。中文与英文必须指向同一种花、具有对应的具体程度。
4. 只有可见的花形、花瓣结构、花心等特征足以支持花名时才返回。不要只凭颜色、插花搭配或相邻花材猜名称，不要从标牌、招牌或文字推断花名。
5. 模糊、遮挡严重、过小、无法可靠判断常见花名的候选跳过。只能判断为“花”“植物”“菊类”等模糊大类时也跳过，不用候选名单或“可能是某花”占用标签。
6. 同种花只返回一次，不因颜色、大小或同义名称不同而重复。不同颜色的同一种花不分别计数。
7. 超过 10 种时，优先选择识别特征清楚、有足够依据判断花名的种类，再优先选择较近、较大的代表花朵。少于 10 种可以，不凑数；没有符合条件的花时返回 {"objects":[]}。

定位规则：
1. 每种花选择最清楚的一朵作为代表；对于绣球等由许多小花组成、需要作为整体辨认的花序，可选择一团完整清楚的花序。
2. bbox 贴近该代表花朵或花序的可见范围，不把整束混合花、整株、花盆或大片叶子一起圈入，不猜被遮挡的完整边界。
3. 每项增加 anchor: [x, y]，选择代表花朵或花序可见部分上清楚的一点；它必须在该项 bbox 内，不能落在背景、其他花或叶子上。不要机械取 bbox 中心；若找不到可靠落点，跳过该候选。
4. bbox 格式固定为 [xmin, ymin, xmax, ymax]，以完整图片左上角为原点，x 向右、y 向下。
5. x 按图片宽度、y 按图片高度分别归一化到 0–1000。返回数值，满足 0 <= xmin < xmax <= 1000，0 <= ymin < ymax <= 1000，不返回原始像素坐标或 0–1 坐标。
6. anchor 的 x、y 也按图片宽高分别归一化到 0–1000，返回数值。anchor 是目标指向点，不是文字位置；不要为文字避让改变真实 bbox 或 anchor。

输出格式：
顶层只有 objects 数组。每项仅包含 name_zh、name_en、bbox、anchor 四个字段。不要生成 description、科普、养护、品种推测或置信度数字。
结构示意，必须替换成照片中的实际结果，不要照抄占位内容：
{"objects":[{"name_zh":"常见中文花名","name_en":"English flower name","bbox":[100,100,200,200],"anchor":[150,150]}]}

输出前检查：每个花名有足够外观依据，中英文对应，类别不重复，bbox 只圈代表花，anchor 在 bbox 内且实际落在花上，数量不超过 10。只输出最终 JSON。
```

## 复测建议

当前已有 flower1 至 flower3 的旧结果。下一轮使用相同模型和参数、新对话及新文件名（例如 `results/flowers/flower2-anchor-r1.json`），检查花名依据、重复类别、anchor 在 bbox 内与实际是否落在花上。可以先用 flower2 的密集花束检查点位，再测其余样本。返回数量增加本身不代表效果提升。

花名没有可靠花材记录或人员确认时仍记为“待核实”。脚本默认只回绘 bbox 的框上缘或中心文字；添加 `--show-anchor` 可画点并做几何校验，仍需人工核对是否指中花朵。后续测试 flower3 时，建议遮去测试副本中的花材名牌，避免读到答案；坐标必须对实际输入的同一张图片回绘。
