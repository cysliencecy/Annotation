# 风景识图提示词

当前版本：在原风景提示词基础上增加逐对象 `anchor`，用于下一轮定位测试；尚未实测。既有结果见[风景复测记录](../reviews/风景.md)。

本提示词依据已确认的风景照规则编写；此前版本已完成三张小样本初测。每张最多返回 5 个对象或区域。大区域标签可在区域内择位放置，不强制位于 bbox 中心。

## 可复制的提示词

```text
请分析上传的风景照片，为拍照学英语功能选择并定位最多 5 个清楚可辨的实体或风景区域。只返回最终 JSON，不输出 Markdown、分析过程或额外说明。

一、选择对象和区域
1. 可以选择人物、动物、植物、近景物品、远处单体以及清楚的自然或人工场景区域，例如太阳、摩托车、桥、山脉、树林、水面、天空和云。不要返回描述整幅照片的场景概念。
2. 有清楚可辨的近景物体时，优先选择近景物体。同类物体只选一个清楚的代表，例如多辆摩托车只选一辆；不把分散的同类单体合并成一个对象。
3. 近景对象不足 5 个时，可用显眼且边界容易辨认的场景区域补充。不凑满 5 个。
4. 如果没有近景物体，先选画面显眼、边界容易辨认的单体，例如太阳；再选容易区分的场景区域，例如水面或天空。远处建筑、桥等只在能清楚辨认时选择。
5. 连成一片、可以作为整体理解的山脉或树林可作为一个区域，例如一段连续山脉 mountain range、一片连续树林 forest。彼此分离的树丛或同类区域不要合并成一个大区域；分散的树只选一棵清楚的代表。
6. 远处成排或密集的建筑、桥等人工物体按单体类别处理，只选一个边界清楚的代表，不把整排合并为一个对象或区域。
7. 场景区域中的独立对象可以和区域同时返回，例如 sky 与其中一片清楚可辨的 cloud。两者名称和指向范围应不同，标签布局由显示端处理。
8. 只返回能够根据照片可靠辨认并定位的对象。细节不确定时使用有依据的大类；基本类别也不能确认时跳过。不要猜测地名、具体山名或无法确认的地貌类型。
9. sunset、scenery、view 等描述整幅画面的概念不作为对象标签。标签必须是能指向具体实体或区域的名称。

二、名称和解释
1. name_zh 和 name_en 必须指向同一个对象或区域，并保持相同的具体程度。使用常见、准确的英文名称。
2. 不猜人物身份、动物品种、植物种类、品牌、材质、地点或状态。只有照片有清楚依据时才能使用更具体的名称。
3. description 使用一句简短中文解释最终名称的通用含义，不把未经确认的外观、地点或情境猜测写成事实。

三、边界框
1. 对单体对象，bbox 贴近该对象在照片中的可见范围，不推测画面外或被遮挡的部分。
2. 对场景区域，bbox 覆盖该区域在照片中的可见范围。天空、水面、山体或树林可以使用较大的框；大框本身不算错误，但不要把彼此分离的区域合并起来。
3. 场景区域与其中的独立对象可以重叠，例如 sky 区域框可以包含 cloud；每个框仍须对应自己的名称。文字位置由显示端安排，不要为避让文字而改变 bbox。
4. bbox 顺序固定为 [xmin, ymin, xmax, ymax]。以完整输入图片左上角为原点，x 向右、y 向下。
5. 横坐标按图片宽度、纵坐标按图片高度分别归一化到 0–1000。返回数值，不要使用 0–1 或原始像素坐标。
6. 必须满足 0 <= xmin < xmax <= 1000，0 <= ymin < ymax <= 1000。
7. 每项增加 anchor: [x, y]，使用与 bbox 相同的 0–1000 坐标，必须在自身 bbox 内。对太阳、桥、摩托车等单体，指向所选代表的可见部分；对天空、水面、树林等区域，选择区域内清楚属于该区域的位置，避开其中独立物体、其他区域和边界。不要机械使用 bbox 的几何中心。
8. anchor 是内容指向点，不是文字底板的位置；不能可靠选点的对象或区域应跳过，不为了文字避让改动 bbox 或 anchor。

四、输出格式
顶层仅包含 objects 数组。每个对象仅包含以下五个字段，不增加其他字段：
- name_zh：中文名称字符串
- name_en：英文名称字符串
- description：一句简短中文释义字符串
- bbox：[xmin, ymin, xmax, ymax] 四个数值
- anchor：[x, y] 两个数值，位于 bbox 内且指向所命名的对象或区域

结构示意，必须替换成当前照片里的实际对象和坐标，不要照抄：
{"objects":[{"name_zh":"中文名称","name_en":"English name","description":"一句中文释义。","bbox":[100,100,200,200],"anchor":[150,150]}]}

输出前检查：对象或区域确实存在；近景优先规则已执行；同类对象没有重复；远处人工物体没有合并成整排；场景区域范围清楚；中英文一致；bbox 和 anchor 均指向所命名的对象或区域。只输出最终 JSON。
```

## 测试方法

先用相同模型和可见参数，在新对话中上传 `images/scenery1.jpeg`，发送上方完整提示词，不附旧输出；保存为新的 `results/scenery/scenery1-anchor-r1.json`。重点检查 sky、water 的 anchor 是否位于清楚区域，sun、bridge 是否落在实体上。再测 scenery2、scenery3，分别保存新文件，不能覆盖既有结果。记录模型、参数、提示词标识和时间。

`visualize.py` 默认按 bbox 绘制框上缘或框中心文字；添加 `--show-anchor` 可画出并校验模型给的点。分别检查对象选择、命名、区域框范围和 anchor 实际落点；几何有效不等于指向正确。三张旧照片只用于定向排查，不能代表模型整体效果。
