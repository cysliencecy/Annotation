# 食物识图提示词

当前版本：食物 anchor 提示词 v2（2026-10-23）。针对 food2 至 food5 的回绘问题，明确“一处代表”、先选目标点再画框，以及点位与名称的最终核对。用户已确认 food5、food4 均在各自新对话完整使用本页提示词；food4 的米饭点位及大框仍失败，本版定向回归未通过。证据见[食物复测记录](../reviews/食物.md)。

用途：拍照学英语的食物场景。此版本依据已确认的产品规则和旧版小样本问题修订，仅在 food4、food5 做过同图定向复测，不代表整体效果。日常随手拍需使用另外的场景规则。

## 可复制的提示词

```text
请分析上传的食物照片，为拍照学英语功能选择并定位最多 5 类主要食物。只返回符合下方结构的 JSON，不要输出 Markdown、分析过程或额外说明。

一、选择对象
1. 只选择图片中实际可见的食物，排除碗、盘、杯、筷子、包装、桌面等非食物对象。
2. 按食材类别选择对象，例如肉片、洋葱、香菜各标一次，不逐片或逐瓣重复标注。同类只返回一个对象。
3. 同一组食物不同时返回整体和局部名称。例如已返回草莓、蓝莓时，不再返回覆盖它们的“浆果”或“水果拼盘”；只有无法进一步区分、但有依据确认是浆果时，才使用“浆果”。
4. 仅选择有足够可见外观依据判断类别、且能明确定位的对象。过小、模糊或遮挡导致无法判断时跳过，不靠上下文猜测。
5. 超过 5 类时，优先选择画面中显眼、代表对象较大且完整的食物，小配料和点缀放后面。最多 5 个，不凑数；没有可可靠识别且定位的食物时返回 {"objects":[]}。

二、命名与解释
1. 使用图片有依据支持的最具体名称。无法判断细分类时退到可判断的大类；大类也无法判断时跳过。
2. 例如能够判断是肉片但无法确定肉种时，返回“肉片 / meat slices”；只能判断是肉时，返回“肉 / meat”。不能仅凭颜色、酱汁或菜肴搭配断言牛肉、猪肉等具体肉种。
3. “腌制”“烤制”等修饰同样需要依据；不要把“烤肉”作为未知肉种的通用名称。
4. name_zh 和 name_en 必须指同一对象、采用相同的具体程度。英文使用常见、正确的名称，不添加中文。
5. description 是一句简短中文释义，解释最终名称的含义，可包含可靠的通用知识。例如“胡萝卜是一种常见的根类蔬菜”，或“肉片是切成片状的肉”。
6. 不推测图中食物的口感、味道、新鲜程度、烹饪过程或具体用途。不要将通用知识写成对图中食物的事实判断，也不要在解释中补回名称里无法确认的细分类。

三、定位
1. 每类先选最清楚的一个单体，或边界清楚的一小簇作为代表。即使米饭、肉块或肥肠分布在整盘，也只选其中一处清楚可见的部分；不要用一个大框圈住整盘或所有同类。
2. 对每个代表先确定 anchor：把点放在该食物可见部分的内部，尽量避开边缘、遮挡、反光及与其他食材交界处。不要机械使用整盘中心或预想的 bbox 中心。葱花等小目标若找不到能明确落在目标上的点，直接跳过。
3. 再围绕同一处代表画 bbox，只框它的可见部分，不跨越其他食材去囊括分散的同类。像米饭被肉盖住时，只框一处露出的米饭，不把上面的肉一起当作米饭范围；肉也只框一片或一小簇，不把下面的米饭圈进大框。
4. bbox 可包含少量不可避免的背景或遮挡物，不要求像素级分割；但如果框的大部分是另一种食材，或框几乎覆盖整盘，就缩到代表对象。仍无法清楚框选时跳过该候选，不靠放大框凑结果。
5. bbox 和 anchor 必须指向同一处代表。逐项核对：点实际落在 name_zh/name_en 所命名的食物上，而不是另一项食物上；点在自身 bbox 内。两个框可以因真实遮挡而部分重叠，但不能因此交换两项的点位。
6. 按真实位置返回坐标，不为给文字腾地方而移动点或框。anchor 是目标指向点，不是标签文字的位置；文字避让由显示端处理。
7. bbox 顺序固定为 [xmin, ymin, xmax, ymax]，anchor 为 [x, y]。两者都以输入完整图片左上角为原点，x 向右、y 向下，按图片宽高分别归一化到 0–1000；返回数值，不返回字符串。bbox 满足 0 <= xmin < xmax <= 1000、0 <= ymin < ymax <= 1000；anchor 在 0–1000 内且位于自身 bbox 内。

四、输出格式
顶层仅包含 objects 数组。每个对象包含以下五个字段，不增加其他字段：
- name_zh：中文名称字符串
- name_en：英文名称字符串
- description：一句简短中文释义字符串
- bbox：四个数值组成的数组 [xmin, ymin, xmax, ymax]
- anchor：两个数值组成的数组 [x, y]，须在 bbox 内且指向代表食物

结构示意（占位内容和坐标必须替换为实际图片结果，不要照抄）：
{"objects":[{"name_zh":"中文名称","name_en":"English name","description":"一句中文释义。","bbox":[100,100,200,200],"anchor":[150,150]}]}

输出前逐项检查：名称是否有图像依据；每项是否只选一处代表；bbox 是否主要覆盖该代表；anchor 是否真正落在该项命名食物上；相邻食材的点是否被交换；数量、字段和坐标范围是否合规。任何一项无法可靠命名或定位就删除，不为了凑满 5 项保留。只输出最终 JSON。
```

## 最小复测方式

1. 先记录实际模型（当前分别有 GLM-4.6V 与 GLM-5.3-Flash）、可见参数、实际输入图（是否裁剪）、提示词版本“食物 anchor v2”和是否独立新对话。不要把旧提示词下的输出当作本版结果，也不要把提示词和模型同时变化的两轮当作严格模型对照。
2. food5、food4 已确认在各自新对话完整使用本页“可复制的提示词”。仍需补记可见参数、图片是否经过裁剪或压缩、是否附过其他材料，以及旧轮是否使用相同条件。不要覆盖这些原始结果。
3. 检查 anchor 数字格式、0–1000 范围和是否在自身 bbox 内，再用 `visualize.py --show-anchor` 回绘，并对照原图检查点是否真的落在命名食物上、框是否只圈一处代表。几何有效不表示视觉定位正确。
4. 将新旧两轮按相同照片逐项对比，分别记录名称、bbox、anchor 的通过、失败、待核实或未验证。改善一张不等于提示词整体有效；若旧图问题减少，再用全新照片检查能否迁移。标签摆放与引线另行验证。

改动依据：旧版定位第 2 条曾同时写“不跨越其他食材”和“用一个大框把所有同类圈在一起”，语义矛盾，本版明确为“不要用大框圈所有同类”。此前 food3 两份输出的葱段、food2 的葱花指向肉面；food4 的米饭与肉片互相指错；food5 的点位较好但肥肠框覆盖整盘。确认使用本版的同图结果中，food5 的框缩小、food4 的肉片点改善，但 food4 的米饭仍指向肉且大框未改；只能判为部分改善，不能断言本版整体有效。
