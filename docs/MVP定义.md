# 自用 MVP 定义：拍照学英语

状态：2026-10-28 更新。相册选图与识别范围沿用 2026-10-23 的自用 MVP；本次确认照片探索交互。用于先由项目作者本人体验最小闭环，不是公开上线计划，也不代表用户需求或模型准确率已获验证。本页优先于[早期 PRD](PRD.md)中的 MVP 范围。

## 要看清的效果

选择一张新的日常生活照片后，系统先识别一批物体，在原图上自动展开最多 5 个英文标签，其余已识别且有有效位置的物体显示彩色圆点。用户点击圆点展开英文，再点击英文查看中文含义。第一版重点是亲自走通并观察这一体验，错误结果如实呈现，不做人为校对。

## 第一版闭环

1. 在微信小程序中从相册选一张照片。适用范围先限定为主体清晰、彼此分开的日常生活物体；页面应说明这一范围，不自动识别食物、鲜花或风景场景。
2. 自动调用 **GLM-5.3-Flash**，取得一批合格对象的英文名称、中文名称、简短解释及位置。识别结果总数上限待确认，不能把初始展开的 5 个当成识别总数上限；少返回可以，不猜测或凑数，原始返回不经人工修改。当前[日常场景提示词](prompts/日常.md)仍最多返回 5 个，需在确定总数上限后修订并实测。
3. 系统自动选择最多 5 个英文标签先展开，优先选择识别依据充分、主体清楚且标签容易放下的对象；其余合格对象显示圆点。现有输出没有置信度字段，不能虚构置信度分数；具体排序方式需在实现时验证。
4. 点击圆点只展开对应英文标签，不同时打开释义，也不收起已有标签。用户可以继续展开第 6 个、第 7 个；5 个只限制初始展示数量。
5. 点击英文标签打开[词义卡片](../CONTEXT.md)：英文词、中文名称、一句简短中文解释。选中标签变为同色底、白字，不显示 √；点击其他英文标签切换当前释义。
6. 关闭词义卡片保留已展开标签；在卡片中点击“收起标签”，关闭该卡片并将对应标签变回圆点。再次点击该圆点仍只展开英文，需要再点标签才显示释义。
7. 同一份识别结果中，关闭卡片、收起某个标签或查看其他词义，都不收起其余已展开标签。用户可以重新选图或重试识别，新结果重新建立初始展示状态。

## 图上展示与操作边界

- 英文标签优先以目标中心为文字中心；小物体或发生遮挡、重叠时，文字移到旁边，用引线连接模型给出的有效指向点。完整显示原图，不能为了排版裁图或篡改目标位置。中心、`anchor` 与历史 bbox 中心预览的关系见[标签展示规则](rules/标签展示.md)。
- 每个物体使用一种区分色，该物体的圆点、英文文字和引线使用同色。默认标签白底、彩色字；选中标签同色底、白字，关闭卡片后恢复默认标签样式。颜色用于区分物体，不表示词汇类别或识别置信度。
- 不再提供“更多词汇”入口或图片下方的完整词汇列表。额外的已识别物体通过照片上的圆点发现；圆点只代表已有结果，点击时不调用模型。
- 点击既没有标签、也没有圆点的位置，不触发识别或新增标签。收起只改变显示状态，不删除原始识别对象，也不是人工纠正名称或点位。

若模型没有返回可展示对象、输出格式或坐标无效、调用失败，明确告知并提供重试或换图入口，不伪造图上标签或圆点。无有效位置的结果不通过“更多词汇”兜底；原始输出仍保留，按定位异常处理。名称或指向在语义上出错时，首版不提供手动编辑，便于如实观察问题。

当前“GLM-5.3-Flash＋日常场景提示词”的组合尚未完成实测；这里确定的是自用原型的选型和体验边界，不是模型能力已通过的结论。

## 不在第一版

相机拍摄入口、登录、收藏、历史图鉴、云同步、保存/分享图片、自动场景分类、食物/鲜花/风景专项识别、发音、例句、科普、人工校验与手动改标签。不设置七日留存等用户增长指标。

## 完成判断

在符合范围的自选新照片上，能完成“相册选图 → 自动识别 → 初始标签与圆点 → 展开英文 → 查看词义 → 关闭或收起 → 继续探索或重试”的流程；标签展示遵守上面的布局规则，异常有明确去路。

| 观察场景 | 预期行为 |
| --- | --- |
| 只有 4 个合格结果 | 初始展示 4 个英文标签，不凑足 5 个。 |
| 有 7 个合格结果且能够清楚摆放 | 初始展示 5 个英文标签、2 个圆点；没有“更多词汇”。 |
| 连续点击两个额外圆点 | 依次增加到 6 个、7 个英文标签；保留已展开标签，点击圆点不自动打开词卡。 |
| 点击英文，再关闭词卡 | 显示对应中文名称和一句解释；选中标签同色底白字，无 √；关闭后标签继续显示。 |
| 在词卡中收起标签，再点击其圆点 | 仅该标签变回圆点；再点击只展开英文，其余标签状态不变。 |
| 小物体或标签碰撞 | 文字可以移开，使用同色引线指向原位置；不覆盖文字、不改模型坐标。 |
| 点击无标记位置 | 不调用模型，不生成新标签。 |

这些条件判断交互闭环是否可用，不把个别照片的识别结果或坐标当成模型能力通过，也不宣称用户价值已验证。

## 当前证据与待确认项

- [浏览器临时交互预览](../prototypes/exploration-throwaway/index.html)已获得项目作者认可，使用 daily1 的 4 项结果与 flower1 的 7 项结果演示流程；它没有接入选图或模型服务，不是已完成的小程序。
- 花束仅作为超过 5 项的交互样本，不扩大日常 MVP 的适用范围。两份历史 JSON 都没有 `anchor`，预览使用 bbox 中心，名称和定位未因此得到验证；花束原始输出未提供一句中文解释，预览也不能作为该字段已接通的证据。
- **识别总数上限待确认**：确定后同步修订日常提示词与输出校验，再用新的日常照片验证超过 5 项的真实返回。当前提示词与既有日常样本不能证明这一能力已实现。
- **极端拥挤的处理待确定**：标签避让后仍放不下、圆点与其他圆点无法清楚区分时，需要继续设计并验证；不把恢复“更多词汇”、强行叠字或修改目标点当成已确认方案。
