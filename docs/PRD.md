# 拍照认识世界小程序｜产品需求文档

> 文档状态：早期方案（历史参考；当前自用范围以[MVP 定义](MVP定义.md)为准）  
> 更新时间：2026-09-24  
> 首发平台：微信小程序  
> 产品名称：待定

## 1. 产品概述

### 1.1 一句话定义

用户拍摄或上传一张图片，小程序自动识别画面中的主要物体，将单一语言的名称标签直接标注在图片上；用户点击标签后，可以查看英文学习信息与可信的中文知识解释。

### 1.2 产品定位

产品是一个轻量的“视觉探索工具”，帮助用户随手认识现实世界，而不是专业物种鉴定工具、英语课程或图片翻译工具。

- 对外用户范围：所有年龄段。
- 首版重点用户：12–35 岁、习惯使用手机拍照、对英语或未知事物感兴趣的用户。
- 首版重点场景：旅行、逛公园、居家探索、就餐、学习和社交分享。
- 产品气质：简洁、现代、有探索感，不采用幼儿化视觉。

### 1.3 核心价值

1. 低门槛：无需登录，拍照后即可获得结果。
2. 强视觉反馈：普通照片在数秒内变成带标签的“认知地图”。
3. 兼顾语言与知识：默认英文标签满足英语探索需求，中文知识降低理解门槛。
4. 可信：展示不确定性与资料来源，不把模型猜测包装成事实。
5. 可沉淀、可传播：识别结果进入个人探索图鉴，也能生成标注图片分享。

## 2. 产品目标与成功指标

### 2.1 MVP 目标

- 验证用户是否愿意反复使用“拍照识物”。
- 验证英文图片标签是否能形成明显的产品记忆点。
- 验证探索图鉴和结果分享能否促进留存与自然传播。
- 收集真实场景中的识别错误，为后续模型和内容优化提供依据。

### 2.2 北极星验证指标

**新用户七日内再次完成识别的比例（7 日复访识别率）。**

“再次完成识别”指用户在首次成功获得识别结果后的 7 个自然日内，至少在另一次访问中成功完成一张新图片的识别。

### 2.3 辅助指标

| 指标 | 定义 | 目的 |
| --- | --- | --- |
| 首次识别完成率 | 进入首页的新用户中，成功获得首张识别结果的比例 | 验证首次体验是否顺畅 |
| 识别耗时 | 从提交图片到出现可用标签的时间 | 衡量核心体验速度 |
| 结果错误反馈率 | 被标记“结果不对”的识别对象数 / 总识别对象数 | 衡量结果可信度 |
| 人均识别次数 | 活跃用户在统计周期内完成识别的平均次数 | 衡量使用深度 |
| 图鉴访问率 | 识别用户中访问过探索图鉴的比例 | 验证沉淀价值 |
| 分享率 | 成功识别后完成分享或保存海报的用户比例 | 验证传播价值 |

首版上线前不设置虚假的精确增长目标；基线数据形成后，再制定阶段目标。

## 3. 产品原则

1. **先看到结果，再要求授权。** 首次识别不得被登录、订阅或付费流程阻断。
2. **图片标签保持单一语言。** 同一张结果图中不得中英文混排。
3. **少而清晰。** 默认只标注 3–5 个主要对象，避免标签遮挡画面。
4. **承认不确定性。** 低置信结果使用“可能是”等表达，并提供反馈入口。
5. **隐私默认保守。** 原图默认不在服务端长期保存，不做人脸属性或身份分析。
6. **探索优先。** 不把首版做成背词、课程、签到或积分产品。

## 4. 核心用户场景

### 场景 A：认识身边物体

用户看到不熟悉的日常物品，打开小程序拍照。系统在图片上显示英文标签，用户点击标签查看中文名称、用途和趣味知识。

### 场景 B：探索花草

用户在公园拍摄植物。系统标注主要植物，详情展示常见名称、英文名、物种特征、生长环境和资料来源；置信度不足时明确提示结果可能不准确。

### 场景 C：了解食物

用户拍摄餐桌或食物。系统识别食物名称，详情展示常见原料、来源或饮食文化，不提供热量、医疗建议、过敏判断或食用安全结论。

### 场景 D：制作分享图片

用户对识别结果满意，将带有纯英文或纯中文标签的图片保存或分享，形成可传播的视觉内容。

## 5. 信息架构

底部导航建议保持 2 个一级入口：

1. **识别**：拍照、相册选择、识别结果和知识详情。
2. **图鉴**：本地识别历史、分类浏览、收藏和云同步入口。

账户授权、语言设置、隐私说明、反馈和关于产品放入二级设置页，不单独占用底部导航。

## 6. 核心流程

### 6.1 首次识别

1. 用户进入小程序，无需登录。
2. 首页展示相机主按钮和“从相册选择”入口。
3. 用户拍摄或选择一张图片。
4. 小程序压缩图片并上传临时处理。
5. 页面展示明确的识别中状态。
6. 目标在 3–5 秒内返回图片和 3–5 个主要对象标签。
7. 图片标签默认全部为英文。
8. 用户可切换为全中文标签；切换不触发重新识别。
9. 用户点击标签，打开对象知识卡片。
10. 结果自动进入本地图鉴。

### 6.2 补充识别

1. 用户发现目标对象未被自动标注。
2. 用户点击图片中未标注的区域。
3. 系统以点击位置附近区域为重点再次识别。
4. 若成功，在结果中增加该对象标签；总标签数量应受可读性限制。

### 6.3 错误处理

1. 用户在知识卡片中点击“结果不对”。
2. 系统记录对象、模型结果、置信度和匿名反馈信息。
3. 页面提供“点选区域重新识别”和“重新拍摄”两个入口。
4. 用户不能直接修改、移动、隐藏或删除标签。

### 6.4 分享

1. 用户在结果页点击分享。
2. 系统生成当前语言下的标注图片。
3. 图片可包含轻量品牌标识和小程序码，不得显著遮挡原图。
4. 分享前提示用户检查照片中的人物、住址、票据等隐私信息。
5. 用户可以保存到相册或使用微信分享能力。

## 7. 功能需求

### 7.1 图片输入

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| IMG-01 | 支持调用相机拍摄单张照片 | P0 |
| IMG-02 | 支持从系统相册选择单张图片 | P0 |
| IMG-03 | 上传前进行尺寸与质量压缩，并保留足够的识别清晰度 | P0 |
| IMG-04 | 图片过暗、模糊、过小或上传失败时给出具体重试提示 | P0 |
| IMG-05 | 首版不支持视频、连续扫描和多图批量上传 | 边界 |

### 7.2 对象识别与标注

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| REC-01 | 自动识别并标注画面中 3–5 个主要对象 | P0 |
| REC-02 | 自动判断普通物体、食物、植物等内容类别，无需用户预选 | P0 |
| REC-03 | 每个结果至少包含对象 ID、类别、中英文名、位置、置信度 | P0 |
| REC-04 | 标签锚点应尽量贴近对象，避免相互重叠和遮挡主要主体 | P0 |
| REC-05 | 用户可点击未标注区域发起重点识别 | P0 |
| REC-06 | 低置信结果必须使用不确定性提示 | P0 |
| REC-07 | 不对人物添加身份、年龄、性别或情绪标签 | P0 |

### 7.3 标签语言

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| LNG-01 | 图片标签默认全部显示英文 | P0 |
| LNG-02 | 用户可将整张图片的标签切换为全部中文 | P0 |
| LNG-03 | 单张结果图中禁止中英文混排 | P0 |
| LNG-04 | 语言切换直接使用已有结果，不重新调用识别服务 | P0 |
| LNG-05 | 记住用户最近一次标签语言选择 | P1 |

首次打开默认英文；一旦用户主动切换，后续打开沿用其选择。

### 7.4 知识卡片

所有知识卡遵循“短卡优先、详情展开”。默认摘要为 60–120 个中文字，并展示一个趣味知识点。

**通用字段：**

- 中文名、英文名。
- 英文音标、发音。
- 简短英文例句及中文释义。
- 中文知识摘要。
- 置信状态。
- 资料来源。
- “了解更多”和“结果不对”。

**分类扩展字段：**

| 类别 | 详情内容 |
| --- | --- |
| 普通物体 | 主要用途、常见场景、基本原理或趣味知识 |
| 植物 | 常见名、可能的物种、外观特征、生长环境、分布或花期 |
| 食物 | 常见原料、来源、制作方式或饮食文化 |

内容采用“识别模型 + 可靠资料检索 + AI 简化表达”的方式生成。不得无来源地生成确定性物种结论；不得提供热量、诊疗、过敏、毒性或食用安全判断。

### 7.5 探索图鉴

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| EXP-01 | 成功识别后自动创建本地图鉴记录 | P0 |
| EXP-02 | 支持按全部、物体、食物、植物分类浏览 | P0 |
| EXP-03 | 展示累计识别图片数、对象数和英文词汇数 | P1 |
| EXP-04 | 支持收藏知识对象 | P1 |
| EXP-05 | 未授权用户点击同步或收藏时，再请求微信授权 | P0 |
| EXP-06 | 不提供今日回顾、背词、测试、签到、积分或主动提醒 | 边界 |

### 7.6 账户与同步

- 未登录用户可以完成拍照、相册选择、识别、查看知识和本地历史。
- 需要收藏或跨设备同步时，再发起微信授权。
- 用户主动开启云同步后，才将对应图片或压缩图及识别记录上传云端。
- 用户应能查看同步状态，并删除云端记录和账户数据。

### 7.7 反馈

- 每个对象详情提供“结果不对”。
- 反馈不得要求用户编辑正确答案。
- 反馈成功后提供重新拍摄或点选区域重识别。
- 后台应能按类别、模型版本、置信区间聚合错误反馈。

## 8. 吸引与留存设计

### 8.1 首次吸引

- 首页只突出一个主要动作：拍照识别。
- 首屏用真实示例表达“照片会变成英文认知地图”，避免长篇功能介绍。
- 首次体验不出现登录、收费、广告和订阅消息请求。

### 8.2 核心惊喜时刻

识别完成后，标签应以短暂、克制的动画依次定位到物体上，让用户明显感知照片被“读懂”。动画不得拖慢查看结果。

### 8.3 持续价值

- 图鉴让零散识别积累为个人探索记录。
- 英文词汇数量用于展示探索成果，但不引入学习压力。
- 分类统计帮助用户回顾自己更常探索的内容。

### 8.4 自然传播

- 分享物是图片本身，而不是营销海报。
- 品牌标识和小程序码保持轻量。
- 英文标签适合旅行、生活方式和学习类内容分享。

## 9. 状态与异常

必须覆盖以下状态：

- 未取得相机或相册权限。
- 图片模糊、过暗、过曝或主体过小。
- 未识别到明确对象。
- 仅识别到人物而无可标注物体。
- 网络断开、上传超时、服务繁忙或识别失败。
- 返回结果不足 3 个或超过 5 个。
- 知识资料暂时不可用。
- 本地存储空间不足。
- 云同步失败或登录状态失效。

异常提示需要说明用户下一步能做什么，例如重新拍摄、靠近主体、改善光线或稍后重试，不能只显示“发生错误”。

## 10. 隐私、安全与合规

- 原始图片默认只在本地保留；服务端临时文件在识别完成后删除。
- 云端长期保存必须由用户主动开启同步。
- 上传前默认移除非必要的 EXIF 信息，尤其是精确位置。
- 不进行人脸身份、年龄、性别或情绪识别。
- 分享前提示用户自行检查人脸、家庭环境、票据和地址等敏感信息。
- 隐私政策需说明图片用途、处理位置、临时保存时长、第三方模型服务和删除机制。
- 面向未成年人时，不采集与核心功能无关的个人信息。
- 知识卡应避免将识别结果用于医疗、食用安全或其他高风险决策。

## 11. 非功能要求

### 11.1 性能

- 正常网络环境下，提交图片后 3–5 秒内显示可用标签结果。
- 超过 5 秒时展示持续进度反馈；达到超时阈值后允许重试。
- 语言切换应即时完成，不产生新的网络识别请求。

### 11.2 可用性

- 主要流程应能单手完成。
- 标签文字在复杂背景上保持足够对比度。
- 标签点击区域不得小于微信小程序常用触控尺寸。
- 关键状态不能只依赖颜色区分。

### 11.3 可观测性

核心事件至少包括：进入首页、选择图片来源、提交识别、识别成功/失败、识别耗时、点击标签、播放发音、展开详情、提交错误反馈、点选区域重识别、访问图鉴、授权登录、开启同步、生成分享图和完成分享。

埋点不得记录原始图片内容或不必要的个人信息。

## 12. MVP 验收标准

满足以下条件才可视为首版完成：

1. 新用户无需登录即可从拍照和相册两种入口完成识别。
2. 正常图片可以得到带位置的主要对象标签，且默认仅显示英文。
3. 用户可以一键切换为全中文标签，结果中不出现双语混排。
4. 点击标签可查看英文发音与例句、中文摘要、详细知识和来源。
5. 低置信结果有明确提示，用户可以反馈错误并重新识别。
6. 用户可以点击未标注区域补充识别。
7. 成功结果进入本地图鉴，并能按类别查看。
8. 用户可以生成并保存或分享标注图片。
9. 人物不被进行身份或属性标注。
10. 服务端原图按隐私规则自动删除，用户可删除已同步数据。
11. 关键行为、性能和错误指标可以被统计。
12. 断网、超时、权限拒绝、无结果和低质量图片均有可执行的错误提示。

## 13. 明确不在首版范围内

- 食物热量、营养计算和饮食管理。
- 图片 OCR、菜单翻译和路牌翻译。
- 实时相机 AR 识别。
- 视频、连续扫描和批量图片。
- 用户移动、隐藏、删除或手工修改标签。
- 人脸身份与人物属性分析。
- 医疗建议、过敏判断、毒性或食用安全结论。
- 单词测试、课程、背诵计划、今日回顾、签到和积分。
- 订阅消息提醒。
- 广告、会员和付费能力。
- 多平台客户端同步开发。

## 14. 后续可能方向

后续功能必须由真实使用数据决定，不作为首版承诺：

- 更细的动物、建筑、艺术品等垂直知识卡。
- 实时 AR 或连续探索模式。
- 多语言标签。
- 家庭共享图鉴或主题探索任务。
- 专家或社区纠错机制。
- 根据使用频率、成本和用户意愿决定广告或会员模式。

## 15. 待技术验证事项

- 多物体检测、分类和中英文实体对齐的模型方案。
- 植物细粒度识别的准确率、候选结果和置信度阈值。
- 3–5 秒返回目标在真实移动网络下的可行性。
- 可靠知识源的授权、覆盖率、更新策略和引用格式。
- 英文音标、例句与发音服务的来源和成本。
- 微信小程序本地图片存储空间限制及图鉴清理策略。
- 临时图片自动删除机制的可审计性。
- 分享图片生成质量、字体授权和不同机型的渲染一致性。
